BREAKING: closes the remaining SciPy-parity gaps (SciPy 1.16), and SciPy wins where it differs from 0.2. New: `periodogram`, `csd`, `spectrogram` (modes `psd`, `complex`, `magnitude`, `angle`, `phase`) and `coherence`, with SciPy's signatures, defaults, N-D `axis`, complex input and NumPy broadcasting of `x` and `y` (`{ freqs, Pxx }`, `{ freqs, Pxy }`, `{ freqs, times, Sxx }`, `{ freqs, Cxy }`), also exported from `./web`; they share their segmenting, windowing and DFT with `welch` and `stft` (`welch` is now `csd(x, x).real`, as in SciPy). Every window and alias in SciPy's own table works in `getWindow` and every `window` option, including the new `["chebwin", at]`, `["dpss", NW]`, `lanczos` and `["kbd", beta]` (`"kaiser bessel derived"`, symmetric only), with `WINDOW_NAMES` exported; all checked at 1e-12 against `get_window`. Empty input now returns empty arrays like SciPy (or raises where SciPy does) from every spectral function, `getWindow(name, 0)` returns an empty window, and an `nperseg` longer than the signal now warns with SciPy's text through `onWarning` (default `console.warn`). Breaking: `stft`/`istft` `scaling` is only `"spectrum"` or `"psd"` (`"density"` and `"none"` now throw, as in SciPy); `stft`'s `nperseg` defaults to 256 even with an array `window`; `nperseg`/`noverlap`/`nfft`/`axis` are truncated like Python's `int()` and a negative `noverlap` is allowed; `average` is only validated with more than one segment; a bare number is not a `window` for the spectral functions; wrong window parameter counts throw `TypeError` (SciPy's) instead of `RangeError`; warning messages are SciPy's own text, unprefixed. See the README's "Migrating from 0.2" and "Not supported" sections. Follow-up to #178. Unblocks johnhenry/viaframe#551.
