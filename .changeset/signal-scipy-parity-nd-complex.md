BREAKING: `welch` now returns `{ freqs, Pxx }` (was `{ frequencies, psd }`), mirroring SciPy's `(f, Pxx)` and `stft`'s `{ freqs, times, Zxx }`; no alias is kept. `istft` with `inputOnesided: false` now returns a complex `x` (a `ComplexTensor`, as SciPy does) instead of only its real part, so take `.real` where you relied on the old result. `getWindow` is computed with SciPy's own formulas and can differ from `hannWindow` in the last bit. The rest is additive and closes the SciPy-parity gaps the README used to list: N-D input (`welch`/`stft` take `axis`, `istft` takes `freqAxis` and `timeAxis`, with SciPy's output shapes); complex input to `welch` and `stft` (a `ComplexTensor`; forced two-sided in FFT order, `stft` warns as SciPy does); callable `detrend` (`detrend(segment) -> segment`, per segment); `(name, param)` window tuples (`["kaiser", beta]`, `["gaussian", std]`, `["general_gaussian", p, sig]`, `["tukey", alpha]`, `["exponential", center, tau]`, `["general_hamming", alpha]`, `["general_cosine", coefficients]`, `["taylor", nbar, sll, norm]`) and the names `bartlett`, `flattop`, `parzen`, `bohman`, `nuttall`, `blackmanharris`, `barthann`, `cosine`, `triang`, `tukey`, `exponential` and `taylor`, with `getWindow(window, n, fftbins = true)` matching `scipy.signal.get_window`; new `checkNOLA` and `checkCOLA` (`scipy.signal.check_NOLA` / `check_COLA`); and an `onWarning(message)` option on `welch`, `stft` and `istft` (default `console.warn`) used for `istft`'s failed-NOLA warning and `stft`'s complex-input warning. See the README's "Matches SciPy" section for what is still not supported. Follow-up to #178. Unblocks johnhenry/viaframe#551.
