BREAKING: `welch`, `stft` and `istft` now match SciPy by default: with no options they equal `scipy.signal.welch(x)`, `scipy.signal.stft(x)` and `scipy.signal.istft(Zxx)`, and every option takes SciPy's default and meaning. Changed defaults: `welch` `onesided` false -> true (`floor(nfft/2)+1` bins), `welch` `detrend` false -> `"constant"`, `welch`/`stft` `nfft` next power of two -> `nperseg`, `stft` `onesided` false -> true, `stft` `scaling` `"none"` -> `"spectrum"` (`"psd"` added, `"density"` kept as an alias, `"none"` kept as a non-SciPy raw FFT), `stft` `boundary` none -> `"zeros"` (`"even"`, `"odd"`, `"constant"`, `null` also accepted), `stft` `padded` false -> true, and an `nperseg` longer than the signal is now clamped instead of throwing. New: `welch` `average` (`"mean"`/`"median"`), `nfft` may be any integer `>= nperseg` (Bluestein on top of the radix-2 FFT, no power-of-two restriction). New return shapes: `stft` returns `{ freqs, times, Zxx }` with `Zxx` a `[freqs, times]` ComplexTensor (the frame-major tensor with `.freqs`/`.times`/`.frames` is gone, and the `Spectrogram` type is replaced by `StftResult`); `istft(Zxx, opts)` takes that `Zxx` and returns `{ times, x }`, supports SciPy's `nperseg`, `noverlap`, `nfft`, `window`, `fs`, `inputOnesided`, `boundary` and `scaling`, and round-trips `stft` defaults over the whole signal. `welch` still returns `{ frequencies, psd }`. `detrend: "linear"` on segments of length 1-2 now gives zeros, as SciPy does. See the README's "Matches SciPy" and migration notes. Unblocks johnhenry/viaframe#551.
